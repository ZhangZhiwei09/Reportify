## 1. 目标与验收

**目标**：让用户接入一个 Streamable HTTP MCP Server，Reportify 安全地发现其工具、逐工具授权，
并把授权工具交给 Agent 执行，全过程可审计、可解释、默认拒绝。

**验收标准（可验证）**：

1. `alembic upgrade head` 到 `0004`：新增 `mcp_server`、`mcp_tool_cache`，并为 `tool_definition.source_id`
   补 `FK → mcp_server.id`。
2. Server CRUD：新增/查询/更新/删除（软删：`enabled=false`）；凭证只存 `secret` 表，API 不回传。
3. SSRF：非 `https`（本地回环除外）、带 userinfo、解析到私有/回环/链路本地/元数据地址、跨源重定向均被拒绝；
   每个重定向与 OAuth 发现 URL 逐条校验。负面用例覆盖。
4. 连接测试：成功返回 `server_info`、`protocol_version`、工具数量；失败返回结构化错误并写 `last_error`（脱敏）。
5. 发现：工具写入 `mcp_tool_cache` 与 `tool_definition`，默认 `risk_level=write`、无 grant；重复发现幂等；
   `schema_hash` 变化能检出并记录。
6. 授权：`PUT /mcp/tools/{id}/grant` 写 `tool_grant`（global 维度），`risk_acknowledged` 必须显式；
   撤销后立即从可用工具集中消失。
7. Agent 面：`MCPToolset` 按 run 懒连接，只暴露已授权工具；未授权工具模型不可见；
   调用参数脱敏入 `tool_call_audit` 与 `run_event`。
8. 失败语义：Server 不可达时该 Server 工具从本次 run 移除并记 `mcp_unavailable` 事件，run 继续；
   调用超时记 `timeout` 审计、不重试；未知工具触发缓存刷新。
9. 名称映射：DB 名 `mcp.<slug>.<tool>` ↔ 模型名 `mcp_<slug>_<tool>` 双向一致，冲突时报错。
10. `ruff` 与 `pytest`（单元 + 集成 + Fake Server）全绿；无管理台页面。

## 2. In / Out of Scope

### In Scope

- `mcp_server`/`mcp_tool_cache` 模型与 `0004` 迁移；`tool_definition.source_id` 外键。
- `core/ssrf.py`：统一 URL 校验器（scheme、userinfo、DNS/IP、重定向、发现链路）。
- `modules/mcp/hub.py`：CRUD、测试连接、发现、启停（FastMCP 短连接）。
- `modules/mcp/runtime.py`：Agent 面 `MCPToolset` 构造与过滤。
- `ToolRegistry` 扩展：MCP 工具注册、名称映射、授权过滤（复用 `tool_grant`）。
- `Runtime`：把授权 MCP toolset 注入 run；MCP 工具调用审计与事件。
- API：`/mcp/servers*`、`/mcp/tools/{id}/grant`、`/mcp/audits`。
- Fake MCP Server 测试夹具（FastMCP + 本地端口）。

### Out of Scope

- OAuth 2.1 完整流程与 token 刷新（只保留 `auth_type=oauth` 字段与 `MCPClientFactory` 接口）。
- stdio 传输（架构明确禁止）。
- 审批 UI 与 `waiting_approval` 恢复（M4；M3 只做「默认拒绝 + 显式授权」）。
- MCP 管理台视图（M4）。
- 工具结果缓存、速率限制的持久化计数（M3 只做进程内简单限流）。

## 3. Research Findings

| 事实 | 结论 | 影响 |
| --- | --- | --- |
| M2 已实现 | `ToolRegistry`、`tool_definition`/`tool_grant`/`tool_call_audit`、`AgentRuntime` 事件泵可用 | M3 直接扩展，不改表结构（除新表与外键） |
| M2 依赖 | 当前 pyproject 只有 `pydantic-ai-slim[openai]`；`uv sync` 已移出 `mcp` 包 | 需改为 `[openai,mcp]` |
| PydanticAI | `pydantic_ai.mcp.MCPToolset` 存在（2.71.0 已核实导入路径） | Agent 面用它 |
| MCP SDK | 随依赖安装 `mcp==2.3.0`、`sse-starlette==3.7.0` | Fake Server 用 `mcp.server.fastmcp.FastMCP` |
| 授权模型 | `tool_grant` 已按 `(tool_definition_id, scope, scope_id)` 唯一，`NULLS NOT DISTINCT` | MCP 工具直接复用，无需新表 |
| 审计 | `tool_call_audit.source` 已有 `mcp` 枚举 | 只写 `source='mcp'` |
| Runtime 事件 | M2 的 `_EventPump` 只处理内置函数工具事件 | 需同时处理 MCP 工具事件（`ToolCallEvent`/`ToolResultEvent` 或同一 `FunctionToolResultEvent` 路径，实现时以实测为准） |
| 记录 | `mcp_tool_cache.annotations` 仅记录，不作权限依据 | 授权只看 `risk_level` + `tool_grant` |

> 待实现前实测确认：MCPToolset 的工具调用是否与内置工具共用 `FunctionToolCallEvent`/`FunctionToolResultEvent`。
> 若是独立事件，`_EventPump` 需增补分支；契约测试放在 Execute 第 2 步。

### 5.3 行为细节

**SSRF（硬约束）**

- `scheme` 仅 `https`；`allow_loopback` 时额外允许 `http://127.0.0.1` / `http://localhost`。
- 拒绝 URL userinfo（`user:pass@`）。
- DNS 解析全部 A/AAAA 记录，任一落入以下网段即拒绝：回环、私有、链路本地、组播、保留、`169.254.169.254`。
- 重定向 ≤3 次；每次重新校验；跨源重定向直接拒绝。
- OAuth 发现链路（`resource_metadata`、`authorization_servers`、`token_endpoint`）同样逐条校验（M3 只保留接口）。
- 连接与读取超时显式设置，不依赖默认值。

**连接测试与发现**

- 测试：SSRF → 连接（30s）→ `initialize`/`list_tools` → 更新 `status/last_tested_at/server_info/protocol_version`。
- 发现：写入 `mcp_tool_cache`（含 `schema_hash=sha256(canonical(tool schema))`）与 `tool_definition`
  （`name='mcp.<slug>.<tool>'`、`kind='mcp'`、`source_id=server.id`、`risk_level='write'`）。
- 幂等：同 schema 重复发现不产生重复行；schema 变化时更新缓存并写 `cache_version`，
  已授权工具保留授权但记录告警（不静默扩大能力）。
- 工具减少时：`mcp_tool_cache` 删除对应行，`tool_definition.enabled=false`（保留审计引用）。

**授权**

- 新工具无 grant → 不在 `list_for_run` 中，模型不可见。
- `PUT /mcp/tools/{id}/grant` 必须带 `risk_acknowledged=true` 才能授权 `write`/`destructive`；
  缺省返回 `422 validation_failed`。
- `DELETE` 撤销：将 grant 置 `allowed=false`，立即生效（下一次 `list_for_run` 不可见）。
- `destructive` 每次调用需要审批（M3 只返回 `needs_approval`，审批交互在 M4）。

**Agent 面集成**

- 每个 run 为每个启用且已授权的 Server 构造一个 `MCPToolset`，`include_instructions=False`，
  `tool_error_behavior="retry"`，`read_timeout` 来自 `options`。
- Server 连接失败：该 Server 的工具从本次 run 移除，发布 `error`（`code=mcp_unavailable`）事件，run 继续。
- 工具名前缀 `mcp_<slug>_<tool>`；冲突（同 slug 同 tool）在发现时即报错。

**审计与事件**

- 每次 MCP 调用写 `tool_call_audit`：`source='mcp'`、`tool_name`、`arguments_redacted`、
  `status`（succeeded/failed/timeout/denied）、`error_code`、`duration_ms`。
- 事件：`tool_call`/`tool_result` 与内置工具同构；参数脱敏规则复用 M2。
- 审计写入失败 → 调用按失败处理（不静默）。

**API**

- `/mcp/servers`：GET/POST；`/mcp/servers/{id}`：GET/PATCH/DELETE；`/test`、`/discover`、`/tools`。
- `/mcp/tools/{tool_id}/grant`：PUT/DELETE。
- `/mcp/audits`：按 server/tool/status 过滤分页。
- 错误沿用 07 §3.1；凭证字段永不回传，`has_secret` 布尔代替。

## 7. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| SSRF 防护被绕过（DNS rebinding） | 校验后使用已解析 IP 建连（或在客户端禁用二次解析）；负面测试覆盖 |
| MCP 工具事件与内置不同构 | 先做契约测试；`_EventPump` 增加分支，不改事件表结构 |
| 工具名冲突 | 发现阶段即报错，不覆盖既有定义 |
| 第三方 Server 返回恶意描述 | 描述仅作展示；不注入 instructions；系统指令声明工具输出是数据 |
| 连接泄漏 | 每个 run 一个 toolset，run 结束关闭；管理面短连接 |
| 迁移失败 | 只新增表与一个可空外键；downgrade 可逆 |
