通用型 AI 数据分析与可视化 Agent 平台

用一句话描述你的分析需求，Agent 自动理解数据、规划分析、生成可追溯的 HTML 报告。

Reportify 不是 BI 工具，不要求你懂仪表盘配置。接入 PostgreSQL，告诉 Agent 你想知道什么——它理解字段类型、统计数据特征、调用 Pandas 分析工具、生成包含 ECharts 图表的静态 HTML 报告。每一张图都能追溯到原始查询和计算口径。

01 — 核心链路

从自然语言到数据报告，三步完成。

💬
STEP 01

描述需求

接入 PostgreSQL 数据源，用自然语言告诉 Agent 你想分析什么。不需要预先定义字段含义。

→
⚙
STEP 02

Agent 分析

Agent 自动画像数据、识别字段类型、制定分析计划、调用 Pandas 计算工具、校验结果。LLM 只做理解和规划，不做计算。

→
📊
STEP 03

生成报告

输出 Pydantic 校验的 Schema，Jinja2 渲染为自包含 HTML 文件。含 ECharts 图表、KPI 卡片、数据来源追溯。

02 — 交互演示

用户说一句话，Agent 做全部工作。

即时分析会话

datasource: postgres://app_db · 14 tables · 2.3M rows
USER
帮我分析最近 30 天的数据趋势，找出波动比较明显的字段。
REPORTIFY AGENT
我先获取数据源结构和字段画像，再制定分析计划。
  • inspect_dataset — 发现 14 张表，识别 orders / events / users 为核心表
  • profile_dataset — 自动识别 6 个时间字段、12 个数值字段、23 个分类字段
  • analyze_trend — 计算最近 30 天各数值字段的日聚合趋势
  • detect_anomalies — 基于标准差识别波动超过 2σ 的字段
  • generate_report — 组织分析结论，生成 Report Schema
USER
duration 字段的波动是什么原因？和上周对比一下。
REPORTIFY AGENT
已调用 compare_periods 工具对比最近 7 天与前 7 天的 duration 字段。报告已生成，包含趋势对比图、异常点标注和统计摘要。报告文件：reports/2026-11-15_duration_analysis.html
03 — 定时报告

配置一次，每天自动生成昨天的数据分析。

定时任务配置

cron: 0 9 * * *

用户通过自然语言或 API 配置定时任务。Agent 在指定时间自动获取最新数据、执行分析、生成报告、归档到本地文件系统。

  • 每日数据分析报告 · 09:00已执行
  • 每周趋势对比报告 · 周一 09:00已执行
  • Duration 异常监控 · 每 6 小时等待中
  • 月度数据画像报告 · 每月 1 日等待中

报告归档与追溯

每次定时执行生成独立的 HTML 报告文件，按日期归档存储。执行时的数据快照可追溯，支持对比不同时期的分析结果。

  • reports/2026-11-14_daily.html48KB
  • reports/2026-11-13_daily.html52KB
  • reports/2026-11-12_daily.html47KB
  • reports/2026-11-11_daily.html超时失败
  • reports/2026-11-10_daily.html51KB

05 — 核心架构

七个模块，各司其职。

MODULE 01

Data Connector

统一数据源接入层。MVP 实现 PostgreSQL 连接器，设计可扩展接口。支持表结构发现、分页查询、只读安全校验、连接池管理、超时重试。

SQLAlchemy 2.0 PostgreSQL Read-only
MODULE 02

Data Profiling

自动识别数值/时间/分类/文本字段，计算空值比例、唯一值、分布特征、异常值。不猜测业务语义——status=1 只是分类值，不代表成功。

Pandas Auto-detect
MODULE 03

Metadata & Tag System

用户可为字段添加展示名称、描述、单位、分类、备注。无标签时使用原始字段名和自动识别类型。标签辅助展示，不是分析的前置条件。

Optional Display-only
MODULE 04

Agent Analysis Engine

PydanticAI 构建 Agent，DeepSeek API 驱动。理解自然语言需求、制定分析计划、调用工具、组织结论。LLM 只做理解和规划，不做数据计算。

PydanticAI DeepSeek Tool Calling
MODULE 05

Data Analysis Engine

确定性 Python 计算：描述统计、趋势分析、周期对比、分布分析、异常检测。每个结果包含计算口径、数据范围、样本量、执行时间、质量检查。

Pandas Deterministic Traceable
MODULE 06

Report Engine

Agent 输出 Pydantic Schema → Jinja2 模板渲染 → 自包含 HTML。支持 KPI、ECharts 图表、数据表格、分析结论、数据来源追溯。禁止 LLM 直接生成 HTML。

Jinja2 ECharts Pydantic v2
MODULE 07

Task & Scheduler

定时报告：Cron 配置、自动执行、失败重试、幂等控制、超时管理。ARQ + Redis 异步队列与 FastAPI 集成。报告按日期归档，数据快照可追溯。

ARQ Redis Cron
MODULE 08+

后续扩展：MySQL · CSV · Excel · REST API 数据源

06 — 设计原则

实用优先，不为炫技引入复杂度。

01

LLM 与计算分离

LLM 负责理解、规划和解释。数据获取、统计计算、结果校验全部由确定性 Python 代码执行。不让模型算数。

02

Schema 驱动报告

Agent 输出经 Pydantic 校验的结构化 Schema，Jinja2 模板渲染为 HTML。禁止 LLM 直接生成 HTML 或可执行代码。

03

全链路可追溯

每张图表附带数据来源、查询条件、计算口径。报告元信息包含生成时间、数据源、样本量、执行耗时。

04

查询安全

所有数据查询经过只读校验，禁止 DDL/DML。分页查询避免全量加载，超时控制保护数据源。

05

不猜测业务语义

字段类型识别 ≠ 理解业务含义。status=1 只是分类值。用户标签辅助展示，不是分析的前置条件。

06

模块化单体

优先模块化单体架构，不一开始拆微服务。接口设计可扩展，MVP 控制实现范围，稳步迭代。
